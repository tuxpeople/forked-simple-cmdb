---
id: ISS-107
type: issue
title: Schema creation only ran under __main__, so WSGI deployment served no tables
status: deprecated
since: 2026-08-06
owner: tyson
affects: [cmdb]
---

`init_db()` was called only inside `if __name__ == '__main__':`. Running
`python app.py` therefore worked, and the Dockerfile does exactly that, so the
defect was invisible in every path anyone had tried.

Any WSGI server imports the module instead of executing it. Deploying behind
gunicorn or uwsgi, which is the ordinary way to run Flask in production, would
have created the application object without ever creating the tables, and every
request would have failed with `no such table: servers`.

Found while writing the contract runner: the suite starts the app by importing
it, which is the same thing a WSGI server does, and the first contract failed
with exactly that error. Nothing about the codebase changed to reveal it; only
a second way of starting it.

Resolved 2026-08-06 in feature/contract-runner: `init_db()` now runs at import.
Every statement is `CREATE TABLE IF NOT EXISTS`, so it is idempotent.
