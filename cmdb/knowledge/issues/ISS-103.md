The discover page submits uploads to `/api/import/csv`
(templates/discover.html:161) with the target table in a form field
`type`. The backend routes import as `/api/import/<table>` and accepts
only `servers` or `applications` (app.py:787-791), so `csv` fails the
whitelist and every import attempted from that page returns 400
`{"error": "Invalid table"}`. The page then renders "Import failed:
undefined" because it reads `data.error` on a body whose key it expects
under a different flow.

CSV import does work when called correctly, e.g.
`curl -F file=@servers.csv /api/import/servers`.

Confidence: high; the mismatch is a straight read of the two files. Which
side is wrong (UI should send the table in the path, or the API should
read the `type` field) is Tyson's call; the OpenAPI file documents the
backend as built.
