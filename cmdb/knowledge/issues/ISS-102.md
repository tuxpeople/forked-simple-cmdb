title: Foreign keys are never enabled, so declared cascades are inert
status: active
since: 2026-07-31
owner: tyson
affects: [cmdb]
---

SQLite enforces FOREIGN KEY clauses only when `PRAGMA foreign_keys = ON`
is issued on each connection. No connection in app.py ever issues it, so
all the ON DELETE CASCADE / SET NULL declarations (app.py:88-89, 104-105,
117) are documentation, not behaviour. Observable consequences:

- Deleting a server leaves its services rows pointing at a dead
  `server_id`; same for dependencies and discovery_history
- Deleting an application leaves `services.application_id` dangling
  instead of nulling it
- `POST /api/service/add` accepts a `server_id` that does not exist and
  returns success

The UI half-masks this: list pages use LEFT JOIN so orphans render with
blank server/app names rather than disappearing or erroring.

Confidence: high. This is documented SQLite default behaviour plus the
absence of the pragma, both directly checkable. Fix is one line per
connection; the schema already says what should happen (ASM-104).
