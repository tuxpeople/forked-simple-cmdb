Evidence: app.py:748-766. Confidence: high; verified by curl against a
live instance on 2026-07-31, on the fix/mined-defects branch that
resolved ISS-101. Before that fix this endpoint 500ed on every request.

## Scenario: history is retrievable once a run is recorded

Given at least one discovery_history row exists
When a client GETs /api/discovery/history
Then the response is HTTP 200
And the body is {"history": [...]} with at most 20 items, newest first
And each item carries id, server_id, discovery_type, data, discovered_at

## Scenario: an empty history is a 200, not an error

Given discovery_history has no rows
When a client GETs /api/discovery/history
Then the response is HTTP 200
And the body is {"history": []}
