Evidence: app.py:757-785. Confidence: high.

## Scenario: an unlisted table is rejected

When a client GETs /api/export/discovery_history
Then the response is HTTP 400
And the body is {"error": "Invalid table"}
And there is no "success" key in the body

## Scenario: a listed table downloads as CSV

Given at least one server exists
When a client GETs /api/export/servers
Then the response is HTTP 200 with Content-Type text/csv
And Content-Disposition names an attachment matching servers_export_*.csv
And the first line of the body is the servers column headers
