Evidence: app.py:660-678. Confidence: high. Note this contract asserts
nothing about dependants of the deleted row; that behaviour is currently
an accident (ISS-102) and must be decided before it is contracted.

## Scenario: deleting a service

Given a service with id S
When a client DELETEs /api/service/S
Then the response is HTTP 200 with {"success": true}
And GET /api/export/services no longer contains a row with id S

## Scenario: deleting it again

Given service S was already deleted
When a client DELETEs /api/service/S
Then the response is HTTP 404
And the body is {"success": false, "error": "Service not found"}
