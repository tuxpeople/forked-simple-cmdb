## Scenario: a one-field PUT leaves the others intact

Given a server with hostname "web01", owner "DevOps Team", and empty notes
When a client PUTs {"notes": "patched"} to /api/server/<id>
Then the response is HTTP 200
And the body is {"success": true}
And the server's notes are "patched"
And the server's hostname is still "web01" and its owner is still "DevOps Team"

## Scenario: omitting hostname neither 500s nor nulls it

Given a server with hostname "web01"
When a client PUTs {"ip_address": "10.0.0.9"} to /api/server/<id>
Then the response is HTTP 200
And the body is {"success": true}
And the server's hostname is still "web01"

The same partial-update semantics apply to PUT /api/application/<id> and
PUT /api/service/<id>: only body keys are written, updated_at always
advances, and unknown keys are ignored.
