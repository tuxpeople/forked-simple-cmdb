---
id: ADR-103
type: decision
title: JSON envelope with success flag, HTTP 200 for all successes
status: draft
since: 2026-07-31
affects: [cmdb]
implemented_by: [cmdb]
---

API responses use `{"success": true|false, ...}` rather than REST status
semantics: creations return 200 (never 201) with the new id as
`server_id` / `application_id` / `service_id` (dependency add returns no
id at all), deletes return 200 with a body (never 204). Status codes are
used only for failures: 400, 404, 500.

Eleven endpoints follow the envelope consistently, which reads as a
pattern choice. The discipline is partial: the export/import guard
responses drop the `success` key (`{"error": "Invalid table"}`), and
`/api/stats` and `/api/discovery/history` return bare data with no
envelope. The OpenAPI file records each endpoint's actual shape;
regeneration must preserve them per endpoint, not "clean them up".

Confidence: medium that the envelope was chosen; high for the per-endpoint
shapes themselves (read directly from the code).
