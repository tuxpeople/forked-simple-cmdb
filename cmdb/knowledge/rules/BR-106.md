title: CSV import skips duplicates silently and reports only inserted rows
status: active
since: 2026-07-31
affects: [cmdb]
implemented_by: [cmdb]
verified_by: [CT-106]
---

CSV import uses `INSERT OR IGNORE`: rows that collide with an existing
hostname (servers) or name (applications) are skipped without error, and
`imported` in the response counts only rows actually inserted
(`rowcount > 0` check, app.py:829-830). Importing the same file twice
therefore reports `imported: 0` the second time, still with HTTP 200.

Per-row exceptions are collected into an `errors` array of strings, and
the response is `success: true` even when every row failed. Import is
best-effort by design: partial success is success.

Only six server columns and five application columns are read from the
CSV; any other columns are ignored (app.py:810-827).

Confidence: high for the mechanism, which is explicit in the code.
Confidence: medium that "success even when all rows error" is a decision
rather than an unconsidered default.
