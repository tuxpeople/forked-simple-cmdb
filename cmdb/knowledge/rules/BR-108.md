---
id: BR-108
type: business-rule
title: Deletes are hard and not idempotent
status: active
since: 2026-07-31
affects: [cmdb]
implemented_by: [cmdb]
verified_by: [CT-107]
---

DELETE on a server, application, or service removes the row permanently.
There is no soft delete, tombstone, or undo. The first DELETE returns 200
`{"success": true}`; repeating it returns 404 (BR-104), so delete is not
idempotent at the HTTP level.

What deletion does to dependants is currently governed by ISS-102: the
schema declares cascade/set-null intent, but nothing enforces it, so
dependants survive with dangling ids. This rule records only the direct
behaviour; do not read a cleanup guarantee into it.

Confidence: high for the observable behaviour (app.py:492-510, 577-595,
660-678, all `DELETE FROM ... WHERE id = ?`). See ADR-102 for whether hard
delete was a choice.
