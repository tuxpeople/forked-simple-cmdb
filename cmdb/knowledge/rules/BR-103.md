Records created through the JSON API receive defaults for omitted fields:

- Server: `environment` = `production`, `status` = `active` (app.py:442-443)
- Application: `criticality` = `medium` (app.py:528)
- Service: `protocol` = `tcp`, `status` = `running` (app.py:613)
- Dependency: `dependency_type` = `requires` (app.py:695)

These are API-path defaults, not database truths: CSV import and
`demo_data.py` bypass most of them (imported servers get `environment`
NULL; demo dependencies get `dependency_type` NULL). Only `servers.status`
and `services.status` also have schema-level DEFAULTs (app.py:44,81), so a
row's provenance changes which defaults it carries.

Confidence: high for the defaults themselves; they are literal in the code.
Confidence: medium that the API/import inconsistency is intended rather
than an oversight.
