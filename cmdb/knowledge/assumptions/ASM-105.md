The README documents capability that does not exist in the repository:

- `DATABASE_PATH` and `FLASK_ENV` environment variables (README.md:167-168).
  The application reads neither. It reads `CMDB_DB`, `PORT`, `FLASK_DEBUG`, and
  `CMDB_HOST`.
- Discovery scripts `discover_linux.py`, `discover_windows.ps1`,
  `discover_network.py`, plus `export_all.py` / `import_data.py` (no such
  files are tracked)
- "Search functionality" and "Bulk operations" in the UI

Assumed: these are aspiration written ahead of implementation, and the
code is authoritative where they disagree.

Confidence: high that the gap exists (verified against `git ls-files` and
app.py); the "aspiration, not lost code" reading is supported by the roadmap
section but is still an inference.

Corrected 2026-08-06. This previously said the DB path was hardcoded, citing
app.py:24. That line now reads `DB_PATH = os.environ.get('CMDB_DB', 'cmdb.db')`,
so the path has been configurable since the mitigation work, and the item was
citing as evidence the exact line that disproved it.

The mismatch has changed shape rather than closed, and the new shape is worse.
Configurability now exists under a different name, so a reader following the
README sets `DATABASE_PATH`, is silently ignored, and never learns that
`CMDB_DB` would have worked. Renaming one or the other closes this.
