---
id: ASM-101
type: assumption
title: PUT is full replacement; omitted fields are meant to be cleared
status: draft
since: 2026-07-31
affects: [cmdb]
implemented_by: [cmdb]
---

All three PUT handlers write every editable column from `data.get(...)`,
so a field omitted from the request body is overwritten with NULL
(app.py:467-478, 552-563, 635-645). A PUT omitting `hostname` on a server
even 500s, because NULL then violates NOT NULL.

Assumed: the author intended replace-the-record semantics, and the bundled
edit modals (which always send every field) are the only expected caller.

Confidence: low. This may equally be a bug that became load-bearing: no
code comments, no README mention, and PATCH-style partial update is what
small tools usually want. Written as an assumption, not a rule, on
purpose. If Tyson confirms replace semantics, promote to a rule; if not,
this plus the UI is why data loss has never been noticed.
