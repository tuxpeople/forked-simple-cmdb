---
id: ASM-102
type: assumption
title: Deployment is single-user on a trusted network
status: draft
since: 2026-07-31
affects: [cmdb]
---

The application has no authentication, no sessions in use, no CSRF
protection, and no per-user anything. The README roadmap lists "REST API
authentication" and "Multi-user support" as future work, which reads as a
conscious deferral rather than an oversight.

Assumed: the supported deployment is one operator running it on localhost
or a trusted LAN, and every network peer is trusted with full write and
delete access.

Confidence: medium. The roadmap supports the deferral being deliberate,
but nothing in code or docs states the trust boundary, and the app binds
0.0.0.0 by default (app.py:850-852), which undermines the assumption in
practice. See RISK-101 and RISK-102.
