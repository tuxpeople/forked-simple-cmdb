title: Referential cleanup was believed to be handled by the schema
status: active
since: 2026-07-31
affects: [cmdb]
---

The schema carefully declares cleanup intent: services cascade when their
server is deleted, `application_id` nulls out when the application is
deleted, dependencies cascade when either service is deleted,
discovery_history cascades with its server (app.py:88-89, 104-105, 117).

Assumed: the author believed these clauses execute, and the *intended*
delete semantics of the system are cascade/set-null as declared.

They do not execute, because SQLite ignores FK clauses unless
`PRAGMA foreign_keys = ON` is issued per connection, and it never is
(ISS-102). This item preserves the intent so a regeneration can implement
what was meant, not the accident.

Confidence: high, raised from medium on 2026-08-06. The declarations are no
longer inert: ISS-102's fix routes every connection through `get_db()`, which
issues `PRAGMA foreign_keys = ON`, so the cascades this item guessed were
intended now execute. Fixing the system to match the guess is about as strong a
confirmation of intent as this tree can offer, and the item stayed draft at
medium for six days after it arrived.
