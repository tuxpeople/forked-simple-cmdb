title: Field vocabularies are conventions, not validated enums

`status`, `environment`, `criticality`, `protocol`, `os_type`,
`dependency_type` all accept any string. The vocabularies the system
appears to intend exist only as defaults and sample data: `active` /
`running` as defaults, `production` / `staging` / `development` in
demo_data.py, criticality `low`..`critical` in the README.

`/api/stats` groups by these raw values, so `Production` and `production`
would count as different environments.

Assumed: free text is acceptable and consistency is the operator's job.

Kept active rather than superseded. BR-110 proposes fixed vocabularies and is
still draft, so it describes what the system should do; this describes what it
does. Retiring the second in favour of the first left nothing describing the
behaviour the system actually has, which schema 0.5.0 now rejects.

Confidence: the absence of validation is certain (no check appears
anywhere in app.py); that this is intended rather than unbuilt is low
confidence. The README's "Set criticality levels (Low, Medium, High,
Critical)" suggests an enum was imagined but never enforced.
